# Формуляр

Учебный тренажёр по оформлению организационно-распорядительных документов
по ГОСТ Р 7.0.97-2025. Написан на чистых HTML, CSS и JavaScript.

Название взято из делопроизводства: **формуляр документа** — это набор
реквизитов и порядок их расположения на листе. Ровно то, что студент
собирает на каждом уровне.

Знак повторяет механику тренажёра: лист с пустыми полями и карточка,
встающая в одно из них. Он собран инлайновым SVG в `index.html`
(классы `brand__*`) и красится токенами палитры, поэтому работает
в обеих темах без отдельных файлов.

Студент вводит имя и проходит двенадцать уровней подряд, перетаскивая реквизиты
на бланк. Правильный реквизит встаёт в документ и отмечается зелёной
галочкой, неправильный подсвечивается красным крестом, возвращается в банк
и разбирается в панели внизу. За уровень начисляются очки и выставляется
оценка по пятибалльной шкале.

**Уровни открываются последовательно.** Следующий уровень становится
доступен, только когда предыдущий пройден **без единой ошибки** — одна
неверная карточка, и уровень придётся пройти заново начисто. Закрытые
уровни заштрихованы, приглушены и не нажимаются.

## Запуск

Сборка не нужна — зависимостей нет.

* **Просто открыть:** двойной клик по `index.html`.
* **Через локальный сервер** (рекомендуется, ближе к боевым условиям):

```bash
python3 -m http.server 8000
# затем открыть http://localhost:8000
```

* **GitHub Pages:** Settings → Pages → Source: ветка проекта, папка `/ (root)`.

Прогресс и имя студента хранятся в `localStorage` браузера. Кнопка «Выйти»
в шапке очищает сохранённые результаты.

За двенадцать уровней студент встречает **все реквизиты 01–30**. Единственное

только как карточка-ловушка, потому что на одном бланке размещается что-то
одно — герб, эмблема или товарный знак, а все бланки тренажёра используют
первые два.

В каждом уровне есть **карточки-ловушки** —
реквизиты, которые в этом виде документа не оформляются (например,
«наименование вида документа» в письме или «адресат» в приказе).
Если студент попытался их поставить, на экране результата появится
объяснение, почему они сюда не подходят.

> **Важно.** Состав и нумерация реквизитов приведены по ГОСТ Р 7.0.97-2025
> «Организационно-распорядительная документация. Требования к оформлению
> документов». Перед использованием в учебном процессе сверьте формулировки
> с действующей редакцией стандарта — правки вносятся только в файл
> `js/data/docs-topic.js`.

## Фотография разработчика

Блок «Разработчик» открыт всегда и стоит первым на главной странице — выше
приветствия студента. Он собирается один раз при запуске (`js/app.js`,
функция `developerCard()`), поэтому перерисовка списка уровней его не
затрагивает и он не дублируется при возвратах.

В `img/developer.jpg` лежит готовый кадр «лицо и плечи» — квадрат 560×560,
53 КБ, вырезанный из исходной карточки. Исходник сохранён рядом как
`img/developer-original.jpg`. Чтобы заменить фотографию, положите на место
`developer.jpg` квадратный снимок: круглую рамку даёт CSS, ничего
подстраивать не нужно. Если файла не окажется, в рамке покажутся инициалы
и страница продолжит работать.

`build.js` встраивает фотографию в `dist/index.html` как data-URI, чтобы
однофайловая версия оставалась автономной.

## Оформление

Две темы: светлая по умолчанию и тёмная. Переключатель — в шапке, а на
экране приветствия в правом верхнем углу; выбор запоминается в браузере.
Вся палитра объявлена токенами в начале `css/style.css`, тёмная тема
переопределяет только их, поэтому новый компонент получает обе темы сам.

Лист документа выдержан в пропорциях настоящего А4: ширина 794 px — это
210 мм при 96 dpi, высота держится отношением 1 : 1,414, поля заданы по
ГОСТ Р 7.0.97-2025 (левое 20 мм, правое 10 мм, верхнее и нижнее по 20 мм),
а по левому полю проходит линия подшивки. Минимальную высоту задаёт
плавающий блок нулевой ширины, поэтому документ длиннее страницы лист не
обрежет, а растянет.

Лист остаётся светлым в обеих темах — это лист бумаги на столе,
а не панель интерфейса; в тёмной теме он чуть теплее, чтобы не слепить.
Поэтому и отметки на нём (зелёная заливка верного ответа, красная — ошибки,
подсказка) заданы отдельными токенами `--paper-*`, которые с темой **не**
переключаются: иначе в тёмной теме тёмный текст ложился бы на тёмный фон.

Шрифты: Unbounded для заголовков, Golos Text для текста, JetBrains Mono
для кода — подключаются с Google Fonts. Бланки документов набраны Times
New Roman: так их и оформляют по стандарту.

Внизу страницы идёт RGB-подсветка — тонкая полоса с переливом и мягким
свечением. При включённом в системе режиме уменьшенной анимации перелив
останавливается.

Оформление опирается на предметный мир документа: фон разлинован в клетку
как бланочная бумага, на приветственном экране стоит круглая печать,
на листе документа отбито поле для подшивки, а уровни, пройденные начисто,
получают штамп «без ошибок». Закрытые уровни заштрихованы и не нажимаются.

## Разбор ошибок

Под игровым полем ведётся журнал: как только студент кладёт карточку не в
то поле, туда добавляется запись — что поставили, куда, почему не подходит
и что нужно в это поле на самом деле.

Причина подбирается по ситуации:

* карточка-ловушка (реквизит, которого в этом виде документа нет) — берётся
  её пояснение из поля `note`;
* верная карточка не в своём поле — сообщается, где её настоящее место.

Каждая запись заканчивается блоком **«Основание»** со ссылками на пункты
нормативных документов. Те же ссылки выводятся на экране результата.

Над бланком идёт полоса обратной связи — одна на оба случая:

* верный ответ — зелёная полоса с похвалой: какой реквизит поставлен верно,
  с какой попытки и сколько очков принёс («Правильно, молодец!», «Верно!
  Отличная работа», «Так держать!»);
* неверный — красная полоса с ободрением и приглашением попробовать снова
  («Неправильно — попробуй ещё!», «Пока мимо. Попробуй ещё раз!»).

Фразы чередуются, оба списка — в `js/game.js`, константы `PRAISE` и
`ENCOURAGE`. Подсказки внутри самого поля («Реквизит 05 — наименование
организации») убраны: что именно требовалось, студент читает в разборе
ошибок внизу, в строке «Сюда нужно».

Повтор той же пары «карточка + поле» новой записи не создаёт: подсвечивается
уже имеющаяся. Журнал очищается при перезапуске уровня.

Набор устроен так, что одним безупречным прогоном его не закрыть: идеальное
прохождение всех двенадцати уровней даёт 16 из 22, а оставшиеся требуют
другого поведения — ошибиться и разобрать ошибку, читать подсказки,
перезапускать уровень, вернуться к сложному уровню, провести за тренажёром
время.

Полученное достижение выезжает в правом нижнем углу — как в игровых
клиентах. Если сразу выдано несколько, показ каждого сокращается, чтобы
очередь не растянулась.

Список и условия — в `js/achievements.js`: определения в константе `LIST`,
проверки в `onCorrect`, `onRestart`, `onMistakeLogged`, `onLevelDone`.
Прогресс хранится в `localStorage` вместе с результатами уровней: счётчики
в `stats`, множества вида «собери все» — в `sets` (освоенные номера
реквизитов и уровни, где открывали подсказку).

## Профиль

Открывается по клику на имя в шапке. Показывает карточку студента,
сводку (уровней без ошибок, пройдено, оценка, достижений) и сетку всех
достижений: полученные цветные, ещё не полученные — серые, со значком
в оттенках серого и подписью, за что их дают.

## Подсчёт очков и оценка

Максимум за одно поле — 100 очков, дальше по числу попыток:

| Попытка | 1-я | 2-я | 3-я | 4-я и далее |
|---|---|---|---|---|
| Очки | 100 | 60 | 30 | 10 |

Итог уровня — процент от максимума, оценка по шкале:

| Процент | 90–100 | 75–89 | 60–74 | ниже 60 |
|---|---|---|---|---|
| Оценка | **5** | **4** | **3** | **2** |

Оценка по теме и общий итог — среднее арифметическое процентов по
пройденным уровням, переведённое по той же шкале. Сохраняется лучший
результат уровня.

Уровень **зачитывается только при нуле ошибок**, то есть при 100 % очков.
За такое прохождение из нижних углов вылетает конфетти и открывается
следующий уровень. Любая ошибка — экран результата пишет «Уровень не
зачтён», конфетти не летит, следующий уровень остаётся закрытым.
Оценка при этом всё равно выставляется: она показывает, насколько близко
студент был к чистому прохождению. Конфетти нарисовано на canvas своими
силами, без библиотек, и не запускается при включённом режиме уменьшенной
анимации.

## Управление

Поле можно заполнить тремя способами — работают одновременно:

1. **Перетаскиванием** мышью, пальцем или стилусом.
2. **Кликом:** нажать на карточку, затем на поле.
3. **С клавиатуры:** `Tab` до карточки, `Enter`/`Пробел` — выбрать,
   `Tab` до поля, `Enter`/`Пробел` — поставить.

После первой ошибки поле начинает показывать подсказку о том, что в него
нужно поставить.

```

js/app.js               экраны, навигация, экран результата

```

Собрать одностраничную версию: `node build.js`. Получится `dist/index.html`
— вся игра в одном файле, открывается двойным кликом без сервера.

Логика и содержимое разделены: чтобы поменять задания, трогать нужно
только файлы в `js/data/`.

## Как добавить свой уровень

Уровень — это объект в массиве `levels` в `js/data/docs-topic.js`.
Новый уровень достаточно дописать в конец массива — он сам встанет в цепочку
разблокировки последним:

```js
{
  id: 'doc-spravka',             // уникальный ключ, по нему хранится результат
  name: 'Справка',               // заголовок в списке уровней
  desc: 'Короткое описание',
  task: 'Что нужно сделать',     // подсказка в шапке игры
  theory: '<p>HTML-текст…</p>',  // раскрывающийся блок «Подсказка по теме»
  boardType: 'doc',              // doc — лист документа, code — блок кода, layout — макет
  blocks: [ … ],                 // содержимое поля
  cards:  [ … ]                  // карточки банка
}
```

Блоки (`blocks`) собираются из простых элементов:

| Тип | Назначение |
|---|---|
| `{ t:'text', text, cls }` | обычная строка; `cls` — например `b-al-center b-strong` |
| `{ t:'slot', id, answer, ph, hint, explain, refs, w }` | пустое поле; `answer` — `id` верной карточки, `refs` — ссылки на пункты |
| `{ t:'row', cls, items }` | горизонтальный ряд (например, дата и номер) |
| `{ t:'block', cls, items }` | вертикальная группа с выравниванием |
| `{ t:'line', items }` | строка кода: текст и поля вперемешку |
| `{ t:'spacer' }`, `{ t:'rule' }` | отбивка и горизонтальная линия |

Карточки (`cards`):

```js
{ id:'r05', tag:'05 · наименование организации', text:'ООО «Гранит»' }  // верная
{ id:'rx-15', tag:'15 · адресат', text:'…', note:'Почему сюда не подходит',
  refs:['ГОСТ Р 7.0.97-2025, п. 4.15 — адресат'] }                       // ловушка
```

Карточка считается ловушкой, если её `id` не указан ни в одном `answer`.
Поле `note` показывается на экране результата, если студент пытался её
поставить. Многострочный текст переносится через `\n`.

## Совместимость

Проверено в Chromium. Используются `pointer`-события, `closest()`,
`dataset`, `color-mix()`, CSS Grid и Flexbox — всё поддерживается
актуальными версиями Chrome, Firefox, Safari и Edge. Интерфейс адаптирован под экран телефона,
перетаскивание работает пальцем.
